Ringkasan Eksekutif

Awasana adalah platform pemantauan darurat yang menyatukan semua peringatan aktif di Indonesia ke dalam satu peta. Data datang dari sumber resmi (BMKG, PVMBG, NASA FIRMS), laporan warga, dan deteksi otomatis dari ratusan CCTV publik yang dibaca oleh computer vision.

Setiap kandidat kejadian diperiksa AI dalam dua tahap untuk menekan false alarm. Kejadian yang terverifikasi disiapkan untuk command center 112, lengkap dengan koordinat, bukti frame, dan instansi yang direkomendasikan. Operator 112 tetap memegang keputusan akhir: AI tidak pernah menelepon 112 sendiri, dan setiap keputusan tercatat di audit log.

01Latar Belakang dan Masalah

Indonesia berada di ring of fire dan menghadapi bencana hampir setiap hari: kebakaran hutan dan lahan, banjir, gempa, longsor, erupsi gunung api, serta kecelakaan dan gangguan keamanan di kota. Masalahnya bukan hanya kejadiannya, tetapi lambatnya informasi.

Bagi warga

  • Informasi tersebar di banyak kanal (BMKG, PVMBG, media sosial, grup chat).
  • Saat karhutla, banyak warga tidak tahu ada api atau asap di dekat mereka.
  • Tidak ada satu tempat untuk melihat rute terhalang, genangan, atau radius larangan gunung api.

Bagi petugas (112, damkar, polisi, BPBD)

  • Laporan sering terlambat dan belum terverifikasi.
  • Waktu terbuang untuk laporan palsu atau duplikat.
  • Ribuan CCTV publik sudah terpasang, tetapi tidak ada yang menontonnya terus-menerus.

02Solusi dan Nilai Utama

Awasana menggabungkan tiga hal yang biasanya terpisah: pemantauan, verifikasi, dan respons.

KumpulkanSumber resmi, satelit, laporan warga, dan CCTV publik masuk ke satu hub.
→
DeteksiYOLO membaca frame CCTV: api, asap, banjir, tabrakan, kerumunan.
→
VerifikasiLLM dua tahap menilai bukti + konteks cuaca dan kejadian sekitar.
→
TampilkanPeta publik real-time via WebSocket, toast untuk kejadian kritis.
→
ResponsOperator 112 memvalidasi lalu dispatch ke command center.

Prinsip desain

  • Human in the loop. AI menyaring dan menyiapkan, manusia memutuskan. Kejadian dengan kepastian di bawah ambang tidak pernah terkirim otomatis.
  • Kejadian tidak pernah hilang. Error API, kuota habis, atau output AI terblokir menghasilkan status "butuh cek manual", bukan dibuang.
  • Transparan. Setiap kejadian menampilkan sumbernya (resmi, satelit, CCTV + AI, warga, demo) dan alasan AI dalam Bahasa Indonesia.
  • Privasi sejak awal. Tanpa face recognition. Wajah dan plat nomor diblur sebelum disimpan atau dikirim ke AI.
  • Jalan tanpa key. Seluruh demo bisa dijalankan tanpa API key, dengan fallback yang diberi label jelas.

03Pengguna dan Peran

W

Warga (halaman publik /)

Melihat peta semua peringatan aktif, menonton CCTV resmi, mengirim laporan, mengikuti perkembangan laporannya, dan menghubungi 112 lewat satu tombol. Warga hanya melihat status "petugas sudah diberitahu", tanpa kontrol dispatch dan tanpa catatan internal.

O

Operator 112 (/operator dan /operator/dashboard)

Satu-satunya peran yang bisa mengirim, memvalidasi, menolak, atau membatalkan dispatch. Melihat bukti pendukung, hasil verifikasi AI, video wall CCTV, dan berkomunikasi dengan pelapor.

S

Sistem (AI + otomasi)

Mengambil data sumber, menjalankan computer vision, memverifikasi kandidat, memulai hitung mundur sesuai aturan otomasi, dan mencatat semua keputusan ke audit log.

05Halaman dan Dashboard Operator 112

Operator punya dua tampilan. Halaman operator (/operator) adalah peta dengan antrean dan kontrol dispatch. Dashboard operator (/operator/dashboard) adalah ruang kerja tiga kolom untuk menangani banyak kejadian dengan cepat.

1. Antrean kerja

Tab Validasi, Hitung mundur, Laporan warga, Semua aktif, dan Riwayat. Ada pencarian, filter, dan aksi massal. Urutan: butuh validasi, lalu hitung mundur, lalu severity. Balasan pelapor ditandai "Pelapor membalas".

2. Ruang kerja

Panel Kenapa terindikasi: deteksi, verifikasi AI dengan bar kepastian dibanding ambang, dan aturan otomasi yang menentukan jalurnya. Lalu bukti pendukung, keputusan dispatch, kirim manual, tutup kejadian, dan catatan.

3. Log aktivitas

Log live semua aksi AI, sistem, dan operator. Bisa difilter per pelaku dan diekspor ke CSV untuk pelaporan dan akuntabilitas.

Panel bukti pendukung

Ditampilkan di atas tombol validasi agar operator memutuskan berdasarkan data, bukan hanya angka AI:

  • Indikator otomatis yang mendukung atau melemahkan dugaan.
  • Kondisi lokasi dari Open-Meteo: suhu, kelembapan, angin, hujan sekarang dan 24 jam, kualitas udara (AQI, PM2.5), ketinggian.
  • Siaran langsung CCTV pendeteksi atau CCTV terdekat, plus rekaman frame saat deteksi (sudah diblur).
  • Kejadian lain dalam radius 15 km untuk melihat korelasi atau duplikat.

08Arsitektur Sistem

Backend FastAPI menyimpan state di hub dalam memori + SQLite dan mendorong perubahan ke browser lewat WebSocket. Frontend React menampilkan peta, feed, dan detail.

Deploy dan jalur video

Vercel (dua service)

  • frontend: build Vite, semua path ke index.html (SPA).
  • backend: FastAPI app.main:app, data di /tmp/awasana.
  • Rewrites: /api/* dan /ws ke backend, sisanya ke frontend. Satu domain, tanpa CORS tambahan.

Video dan vision

  • Video tidak lewat server Awasana. Browser memutar HLS atau player embed langsung dari server pemda, jadi tidak ada beban bandwidth.
  • Computer vision di server terpisah (laptop, PC, atau server GPU) dengan ENABLE_VISION=true, karena terlalu berat untuk serverless.

Pipeline deteksi

Ambil frameWorker bergiliran (default 3 paralel) ambil 1 frame per kamera, jeda minimal 20 detik, koneksi langsung ditutup.
→
YOLO umumKendaraan tumpang tindih = dugaan tabrakan. Banyak orang = kerumunan.
→
YOLO-WorldPrompt teks: api, asap, banjir/genangan, kendaraan terguling. Tanpa training.
→
Aturan konsistensiMuncul di 3 frame berturut-turut, ambang 0,5 (0,3 untuk api/banjir), cooldown 10 menit.
→
Blur + LLMWajah dan plat diblur, lalu ke verifikasi AI dua tahap.
  • Ringan untuk server pemda: hanya satu frame per giliran, tidak menyedot stream terus-menerus.
  • Bisa dibatasi: VISION_CITIES dan VISION_MAX_CAMERAS untuk mengatur beban mesin.
  • Weights kustom opsional: misalnya model api/asap hasil training dataset D-Fire untuk akurasi lebih tinggi.
  • Simulasi terpisah: kejadian simulasi tidak pernah ditempel ke CCTV asli, hanya ke kamera demo. Kejadian di CCTV asli hanya datang dari pipeline vision.

10Verifikasi AI Anti False Alarm

Setiap kandidat dari CCTV, laporan warga, PetaBencana, dan simulator melewati verifier. Provider default Google Gemini lewat REST generateContent, dengan Claude sebagai alternatif (LLM_PROVIDER=anthropic).

Tahap 1: Triage

Gemini Flash-Lite, thinking rendah. Semua kandidat lewat sini. Tugasnya menyaring yang jelas palsu atau tidak relevan dengan cepat dan murah.

Tahap 2: Verifikasi final

Gemini Flash (atau Claude). Hanya kandidat yang lolos tahap 1 dengan severity tinggi atau kritis. Penalaran lebih dalam sebelum masuk jalur dispatch.

Input dan output

Input
  • 2 sampai 4 frame berurutan (sudah diblur)
  • Lokasi dan jam WIB
  • Cuaca dari Open-Meteo
  • Kejadian dan laporan lain dalam radius 15 km
Output JSON terstruktur (wajib)
  • verdict: confirmed, false_alarm, uncertain
  • confidence 0 sampai 1
  • severity, recommended_agency
  • reasoning dalam Bahasa Indonesia
Gagal dengan aman. Diblokir filter keamanan, output terpotong, kuota habis, atau error API apa pun menghasilkan verdict uncertain dan label "butuh cek manual". False alarm dengan kepastian 0,7 ke atas disembunyikan dari peta tetapi tetap tersimpan di database dan audit log. Tanpa API key, verifier heuristik dipakai dan selalu berlabel simulasi.

11Alur Dispatch 112 dan Otomasi

Belum ada API publik 112 Indonesia. Layanan dikelola pemda (command center) bersama Komdigi, dan panggilan otomatis tanpa pengecekan berisiko membanjiri operator. Karena itu Awasana tidak pernah menelepon 112. Adapter simulate (default) hanya mencatat payload, adapter webhook mengirim JSON ke endpoint command center.

JalurSyaratPerilaku
Hitung mundurSeverity tinggi/kritis, verdict confirmed, kepastian ≥ 87%Timer 45 detik. Operator bisa Kirim sekarang atau Batalkan. Tanpa aksi, terkirim saat timer habis.
Butuh validasiSeverity tinggi/kritis dengan kepastian < 87%, verdict uncertain, atau laporan warga (bila diatur)Tidak ada timer, tidak pernah terkirim sendiri. Operator harus Validasi & kirim atau Tolak.
Gempa resmiBMKG, magnitudo 6 ke atasLangsung masuk hitung mundur (bisa dimatikan di panel Otomasi).
InformasiSeverity sedang/rendahTampil di peta, tidak masuk antrean dispatch.

Payload (awasana.dispatch.v1): jenis kejadian, koordinat, alamat, waktu, ringkasan AI, link frame bukti, instansi yang direkomendasikan, dan siapa yang memutuskan. Semua keputusan AI, sistem, dan operator tercatat di tabel audit_log (GET /api/audit).

12Privasi, Etika, dan Keamanan

Privasi

  • Tidak ada face recognition.
  • Wajah diblur dengan OpenCV YuNet (FaceDetectorYN) bila model tersedia.
  • Plat nomor diblur dari sepertiga bawah kotak kendaraan YOLO.
  • Tanpa detektor: gambar diperkecil ke lebar 640 px dan diblur ringan seluruhnya.
  • Blur dilakukan sebelum gambar disimpan atau dikirim ke LLM.

Etika dan akses data

  • Hanya CCTV yang dibuka publik oleh instansi, tanpa membobol pembatasan.
  • Server yang mengunci akses ke domain sendiri (misal Pelindung Bandung, tol Jasa Marga) tidak dipakai tanpa izin pemilik.
  • YouTube tidak diproses computer vision.
  • Untuk produksi: izin tertulis Dishub/Diskominfo, retensi terbatas.

Pemisahan peran

  • Halaman publik tersambung ke /ws tanpa catatan internal.
  • Operator memakai /ws?role=operator.
  • Balasan pelapor hanya bisa dari pemegang token laporan.

Akuntabilitas

  • Audit log lengkap untuk setiap keputusan AI dan manusia.
  • Label sumber jelas (resmi, satelit, CCTV + AI, warga, demo, simulasi).
  • File .env tidak pernah di-commit.

14Skenario Demo (2 Menit)

  1. Buka aplikasi. Peta Indonesia langsung tampil dengan semua peringatan dan indikator LIVE.
  2. Dalam 20 sampai 30 detik simulator memunculkan kejadian baru, toast muncul untuk kejadian kritis. Atau klik Picu kejadian demo: kejadian CCTV muncul, status "Diverifikasi AI...", lalu terverifikasi.
  3. Buka /operator. Klik toast atau feed: peta terbang ke lokasi, panel menampilkan verdict, kepastian, alasan, dan model AI.
  4. Kepastian 87% ke atas: hitung mundur 112 berjalan, operator Kirim sekarang atau Batalkan. Di bawah 87% (contoh Tol Palindra, 82%): status Butuh validasi, operator Validasi & kirim atau Tolak.
  5. Buka Dashboard: antrean, panel "Kenapa terindikasi", bukti pendukung, log aktivitas, dan panel Otomasi.
  6. Kirim laporan dari halaman publik lewat Lapor, lalu balas dari dashboard dengan "Tanya pelapor". Pelapor menerima notifikasi di Laporan saya.
  7. Zoom ke kota, klik marker LIVE untuk menonton CCTV resmi. Di operator, buka Video wall.

15Dampak dan Roadmap

Dampak yang ditargetkan

  • Waktu dari kejadian ke laporan turun dari menit atau jam ke hitungan detik.
  • Operator 112 menerima laporan yang sudah terverifikasi, lengkap dengan koordinat, bukti frame, dan instansi yang tepat.
  • Warga melihat rute terhalang, zona asap, genangan, dan radius gunung api di satu tempat.
  • Jejak audit untuk akuntabilitas keputusan AI dan manusia.

Rencana integrasi pemda

  1. Pilot dengan satu command center (misal Jakarta Smart City atau Bandung Command Center) memakai mode webhook ke sistem tiket mereka.
  2. Kerja sama akses CCTV ATCS/Dishub dengan perjanjian privasi.
  3. Kalibrasi ambang kepastian dan hitung mundur bersama operator, ukur false alarm rate per minggu.
  4. Skala ke PostgreSQL + PostGIS, antrean pesan, dan sumber baru (BNPB/InaRISK, sensor tinggi muka air).

16Batasan Saat Ini

  • Di Vercel hanya /tmp yang bisa ditulis, sehingga state backend bertahan per instance. Produksi perlu database terkelola.
  • Computer vision belum bisa berjalan di serverless; saat ini server vision menjalankan backend lengkapnya sendiri.
  • Data kriminal masih data demo karena belum ada API terbuka.
  • MAGMA tidak punya API JSON resmi, sehingga datanya diambil dari parsing halaman (fallback ke seed bila gagal).
  • Integrasi 112 masih simulasi atau webhook; perlu kerja sama resmi dengan command center pemda.
  • Akurasi deteksi api/asap meningkat dengan weights kustom; YOLO-World berbasis prompt masih rawan positif palsu, yang kemudian ditekan oleh verifikasi LLM dan operator.
Inti Awasana: satu peta, banyak sumber, AI yang menyaring, dan manusia yang memutuskan. Lebih cepat untuk warga, lebih bersih untuk petugas.
Dokumen ini disusun dari kode sumber dan dokumentasi proyek. Angka kamera dan sumber dapat berubah sesuai hasil sinkronisasi CCTV terbaru.
